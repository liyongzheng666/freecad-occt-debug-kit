# 根因验证方法学（Root-Cause Verification）

> 状态：方法学基线（Methodology Baseline）<br>
> 用途：agent 决策回路（`loop/investigate.py`）与评分器（`eval/scorer.py`）的设计依据。<br>
> 关联：[../README.md](../README.md)（路线图）、[../playbook/blend-failure-ontology.md](../playbook/blend-failure-ontology.md)（失效本体）、[../../docs/occ-fillet-debug-agent-architecture.md](../../docs/occ-fillet-debug-agent-architecture.md)。

---

## 0. 一句话

**根因寻找 = 靶向子复现（定位） + 中间态机制证据（机制） + 互斥靶向反事实（因果对齐）。** 三腿缺一，只能算"假设"，不能算"已验证根因"。

---

## 1. 根因 ≠ 修法（repair）

一个能让圆角成功的修法（如"降半径"），与**一打不同根因**都兼容——它只是**绕开了失效区**，没证明病根。所以：

- **repair-based 成功** 只能回答"它能不能被修"，**回答不了"根因是什么"**。
- repair 仅在被约束为 **"只针对所宣称的那个因"** 时，才升级为**反事实验证**（见 §4）。

把目标定在根因，就不能用"随便一个修法成功"来打分。

---

## 2. 代理奖励陷阱（必须先堵住）

`IsDone()` 是**易测的代理**，**几何有效性**才是真目标。把判据建在 `IsDone()` 上，agent 和 eval 会一起对"`IsDone()=true` 但自交/破损"的结果鼓掌——典型的 Goodhart / reward hacking。

> **铁律：成功判据 = 几何有效性**（`BRepCheck_Analyzer` + 自交检测 + G1/切向连续 + 拓扑增量合理），对应本体的 **S6**。`IsDone()` 只是入口闸。

并由此推出 **verifier 强度原则**：

> **验证器的判别力，封顶了整个 eval 的可信度。** 一个布尔 `IsDone()` verifier 没资格验证"几何正确"这种声明。所以加强 verifier（有效性 / 自交 / G1）不是锦上添花，是 eval 成立的前提。

---

## 3. 三腿验证

一个根因结论必须同时过三条腿：

### 腿 1 — 定位（Localization）：靶向子复现

根因必须指到 **具体阶段 + 具体实体**（"S3 面面求交，在 面A 与 blend 面 的某参数区失败"），并通过**把被指控的子操作从整条 fillet 机器里抽出来单独跑**来确认它确实先崩。

- 例（S3）：抽出那两张面，**脱离 ChFi3d 单独跑 `IntTools`/`GeomInt` 求交**，复现同样的失败 → 证明它是这一阶段先崩，而非下游连锁。
- 这比"整体重跑"强得多：它排除了"症状阶段其实是被上游拖垮"的可能。

### 腿 2 — 机制（Mechanism）：中间态证据

必须拿出**该阶段失败的中间态信号**作为证据，而不是断言。

- 例（S3）："SSI 本应返回 1 条 contact 曲线，实得 0 条 / 返回近切退化解。"
- 这正是埋点探针的用武之地——**只为被指控的那一阶段采集**（选择性，不是全打印）。

### 腿 3 — 反事实（Counterfactual）：最小靶向干预

**只修被指控的那个东西，失败应消失**；并用**另一个互斥的靶向修法**做判别。

- 若根因是 S3（SSI 数值病态）：**微调那两面的容差/重参数化** 应能修好，且 **不动半径**。
- 若 **降半径** 才修好、调容差无效 → 根因更可能是 **S2**（球塞不进），而非 S3。

> **不同靶向修法相互排他，正好用来在候选根因间做判别。** 这是把 repair 收编为根因验证的关键：repair 必须**与所宣称的因对齐**，一个随便的修法成功什么都不证明。

---

## 4. 走查示例：SSI（S3）根因的完整验证

症状：`StripeEdgeInter: too big radiuses`（适配层 → 近端 S3，远端候选 S0/S2）。

1. **定位**：从失败现场 capture 相撞的两张面 → 脱离 fillet 跑独立 `IntTools` 求交 → 若同样得 0 交线，定位到 S3（面A×面B）。
2. **机制**：记录"期望 1 条 contact 曲线、实得 0；两面在该区近切（夹角 < ε）"。
3. **反事实判别**：
   - 试 `perturb_tolerance`（只动这两面容差，**不动半径**）→ 若求交成功 → 支持 **S3 数值病态**。
   - 试 `lower_radius`（只动半径）→ 若也成功 → 说明同时存在 **S2** 因素（半径偏大使两面更近切）。
   - 两个修法的成功/失败组合，把根因定位到 S3、S2 或"S2 诱发 S3"。
4. **结论**：输出带定位深度（到 面A×面B）、机制证据（0 交线 + 近切）、反事实（容差修法有效、半径修法亦有效→S2 诱发 S3）、置信度的因果假设。

---

## 5. agent 输出形态：分级因果假设，而非一锤定音

根因寻找是开放难题，agent 常常**只能定位到阶段、定位不到最深机制**。诚实且可校准的产出是：

> **一条按证据强度排序的因果假设链**，每条带：
> - **定位深度**（到 S3 / 到具体两面 / 到机制）
> - **支撑证据**（artifact id + `source:line`，可在 viewer 点开 review）
> - **置信度**
> - **建议的下一步靶向验证**
>
> 证据不足时，**停在能站住的那一层并弃权交人**（人工兜底），而不是硬猜最深根因。

这既诚实，又是好的 harness 设计（校准输出 + 弃权），还天然喂 viewer 的人工 review 面。

---

## 6. 喂给 eval：打分维度与 GT

根因 eval 不能只看"修没修好"。打分维度：

| 维度 | 怎么打 | GT 来源 |
|---|---|---|
| **定位准确率** | 指对阶段 + 指对实体（面/边/顶点） | **instrumented truth run**：埋点版跑出"真正先崩的阶段 + 实体" |
| **机制正确性** | 机制描述与中间态证据一致 | truth run 的中间态（交线条数等） |
| **反事实有效性** | 靶向修法重跑后 **几何有效（S6）**，且与所称因对齐（互斥修法判别正确） | 可执行，自动判 |
| **校准 / 弃权** | 该弃权时是否弃权；置信度与正确率是否对齐 | abstention precision |

**Ground truth 形态**（四元组，多数可由埋点 truth run 自动产出）：

```text
GT(case) = ( 真正先崩的阶段, 涉及实体, 期望的中间态证据, 一个与该因对齐的靶向修法 )
```

> 这比"根因名字符串"客观得多，且天然可执行、可自动判、无需人裁判根因命名。
